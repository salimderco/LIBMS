- All protected pages must redirect unauthenticated users back to the Login page. 
- Role-based server-side protection: Use Next.js Middleware or server actions to restrict unauthorized roles from fetching private data or loading admin routes (e.g., /users). 
- Server-Side Token Invalidation: When a user logs out, fully revoke and invalidate their session/token server-side.

### 2. Built-In Free AI Integration & Fallback
- Install `ai` and `@ai-sdk/google`. Use the `GEMINI_API_KEY` environment variable with the free-tier `gemini-2.5-flash` or `gemini-2.5-flash-lite` models.
- All AI features must be safely wrapped in try/catch blocks. If no key is configured, return mock/fallback data and display a helpful toast notification rather than crashing.

### 3. Core Pages & UI Requirements
- High-end visual design: Use a dynamic, modern Zinc/Emerald or Slate/Teal palette with explicit loading skeletons, interactive hover effects using Tailwind, and responsive desktop/mobile navigation. 
- / (Dashboard): Displays role-specific stat cards.
  * Students/Faculty see: My Active Loans, My Overdue, Books Available, Total in Catalog.
  * Librarians/Admins see: Total Books, Total Users, Active Loans, Overdue count. Includes a live Recent Activity feed driven by the `activity_logs` table.
  * For staff view only: Include a dynamic Recharts BarChart showing the top 5 most-borrowed books with gradient bar fills and custom tooltips.
- /catalog: Advanced catalog browse with search (title, author, ISBN) and filters (category, format, availability, year range). Includes a toggle for grid/list view and server-side pagination.

- /profile: Allows users to update their name, department, or update password securely.

### 4. Database Concurrency & Quotas
- Concurrency Control: The 'Borrow Book' and 'Return Book' actions must be executed within an explicit Prisma interactive transaction (`$transaction`). Two users attempting to borrow the last remaining copy of a book simultaneously must be handled safely so that only one succeeds while the other fails gracefully with a quota or availability error.
- Quota Enforcement: Students are limited to 5 active loans (14-day duration), while Faculty are limited to 10 active loans (30-day duration).
- Renewal Constraints: Max 2 renewals per loan. Each renewal extends the dueDate by the user's standard duration calculated directly from the current dueDate.
- Timestamps: Store and process all dates in UTC.

### 5. Automated Testing Suite
Include a comprehensive suite of backend and frontend tests (using Jest or Vitest) to guarantee quality. Cover these key minimum scenarios:
- Authentication: Valid data creates a user; correct credentials return a session; accessing protected routes without login or after logout returns an unauthorized error; deactivated users cannot log in.
- Catalog Permissions: Librarians can create a resource, but students receive a permission denied error. Searching and filtering work accurately. Attempting to set available_copies directly via an update is rejected.
- Borrowing & Concurrency: A student can borrow an available book, causing available_copies to decrement by exactly 1. Rejects the borrow request if available copies are 0, if the user already has the book on an active loan, or if they have exceeded their quota limit.
- Race Condition Test: Simulate two simultaneous borrow requests on a single available book copy to verify that only one succeeds and the second is rejected.
